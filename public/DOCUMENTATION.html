Project Docs

learningTech (EduSphere)

A modern, full-duplex synchronized learning platform for educators and learners. Features real-time slide synchronization, presence tracking, and touch-optimized interfaces.

Platform Features Guide

🌍 Public vs 🔒 Private Courses

By default, all new courses you create are Private. Private courses are only accessible to you and the specific students you connect to them. If you want to sell or share your course materials with other educators on the Marketplace, you can toggle the course to Public directly from your dashboard!

⏳ Course Expiration Rules

To prevent quota recycling and ensure a fair ecosystem, each course has a strict 13-month lifecycle. The countdown starts the moment the first student enrolls in the course.

After 13 months, the course is permanently Archived (Expired). You will no longer be able to start the class, bulk import students, or invite new students. To continue teaching the material for the next academic year, you must use the Copy Course feature to create a fresh instance and consume new quotas.

⚡ Quick Login (Student Auto-Login)

The Quick Login feature allows students to join your live class without typing passwords!

  1. Visit the /setup page on each physical student device to assign it a unique PC_ID.
  2. Upload a CSV mapping your students to their assigned PC_ID.
  3. Click Enable Quick Login on your dashboard. When students open the platform on their assigned PC, they will be logged in automatically!

Setup Instructions for a New Computer

Because we use .gitignore to protect sensitive information, you must manually copy your sensitive files when cloning this repository to a new computer. Follow these exactly 5 steps:

  1. Add your Environment Variables:
    Copy your local .env file into the main project folder.
  2. Add your Database:
    Copy your local SQLite database file (dev.db) into the prisma/ folder.
  3. Install Dependencies:
    npm install
  4. Generate Prisma Client:
    npx prisma generate
  5. Start the Development Server:
    npm run dev

Open http://localhost:3000 with your browser to see the result.

🤖 Agent Knowledge Base & Development Log

This file documents critical architectural decisions, platform-specific bugs, and framework quirks encountered during development. Future AI agents must review this document to avoid repeating the same mistakes.

Session: July 26, 2026

Features Built: Real-time Teacher-Learner Slide Synchronization, Presence Tracking, and Mobile Compatibility

🚨 CRITICAL FIX: Next.js 15 Local Network JS Hydration Block (Mobile Devices Dead)

The Problem: When testing the application on mobile devices (iPad, Xiaomi phone) via the local network IP (e.g., 192.168.31.222:3000), the page loaded statically but all buttons and JavaScript were completely dead.

The Cause: Next.js 15+ introduced a strict security policy in Development Mode that blocks cross-origin requests for Webpack HMR and JS chunks from other devices on the LAN. The server silently rejects the request, preventing React from hydrating on the client device.

The Fix: You MUST explicitly whitelist the local network IPs in next.config.ts:

const nextConfig: NextConfig = {
  allowedDevOrigins: ['192.168.31.222', '192.168.31.0/24'],
};

🚨 CRITICAL FIX: iOS Safari Modal Clipping (Position Fixed Bug)

The Problem: The Auth modal (position: fixed) was not showing up on iPads/iPhones. The buttons worked, React state updated, but the modal was invisible.

The Cause: Apple's WebKit engine (Safari/Chrome on iOS) has a notorious bug: If a position: fixed element is deeply nested inside a container (like <main>) that has overflow: hidden or a CSS transform, the fixed element gets clipped or trapped inside that container's boundaries.

The Fix: Extracted the modal rendering logic OUTSIDE of the <main> tag using React fragments (<>...</>), making it a direct child of the <body> where iOS cannot clip it.

🚨 CRITICAL FIX: iPad/iOS Touch Hover States

The Problem: Tailwind's group-hover utility works great for mice, but on touch devices, tapping the element did nothing, making the active students tooltip inaccessible.

The Cause: iOS Safari ignores :hover states on taps unless the element is considered "interactive".

The Fix: Added tabindex="0" and an empty onclick="" attribute to the parent div.group. This tricks iOS Safari into treating the element as clickable, instantly making the hover tooltip work perfectly on touch.

🏗️ Architecture Note: Smart Polling for Synchronization

Context: A 1-second polling interval for 35 students generates minimal bandwidth (~3 Mbps) but causes high database read volume (35 reads/sec). A 10-second polling interval saves resources but creates unbearable lag for the Teacher.

Implementation: Implemented a dynamic setTimeout polling loop. When the class is in "Independent Mode", the client polls every 10 seconds. When the teacher clicks "Synchronize", the client instantly shifts to 1-second polling. This delivers a 0-lag presentation experience while conserving resources during downtime.

🏗️ React Note: textContent vs innerHTML

Context: Using .textContent to inject strings that contain HTML tags (like <span class="lang-en">) will literally render the HTML code as text on the screen.

Implementation: When dynamically updating bilingual text via JS, use JS ternaries to select the plain text string based on localStorage.getItem('courseLang') rather than injecting raw HTML. This avoids both XSS risks and broken UI.

🏗️ Architecture Note: PC Identification via Local Storage (Option A)

Context: For school computer labs, the teacher needs to know which PC is mapped to which student without requiring students to log in with passwords.

Implementation: Implement a Local Storage setup mechanism. Before the term starts, an admin opens the website on each PC and inputs a unique PC identifier (e.g., "PC-01"). This is saved in localStorage.setItem('pc_id', 'PC-01'). During class, the website reads this ID and authenticates. The teacher can then upload a CSV mapping PC IDs to student accounts to automatically log them in.

EduSphere Business Plan & Platform Logic

This document outlines the core business logic, pricing structures, and features for the EduSphere platform.

1. Custom Course Creation (Order System)

Educators can order custom interactive courses to be built by the platform team. Pricing is dynamic based on user-selected sliders.

Pricing Bounds

  • Max Price: $1000
  • Min Price: $100

Dynamic Variables (Sliders)

  • Delivery Time: 5 days (Expensive) to 90 days (Cheaper)
  • Number of Free Students: 10 to 60+
  • Number of Total Pages: e.g., 5 to 50+
  • Number of Interactive Pages: 1 to 20+
  • Interactivity Complexity: Basic (Quizzes) to Advanced (Physics/Chemistry Simulations)

Revisions (Changes)

  • Orders closer to $1000 include up to 10 free revisions.
  • Orders closer to $100 include 1 free revision.
  • Purchasing Extra Revisions: $20 for 5 extra revisions.

Refund Policy

  • If an educator is unsatisfied, they can reject the course for a refund.
  • The refund percentage is proportional to the price (e.g., $1000 order = 90% refund, $100 order = 10% refund).

2. Course Marketplace & Privacy

Courses can be either Public (公開) or Private (不公開).

Public Courses

  • Visibility: Anyone on the marketplace can purchase and enroll as a self-paced student.
  • Pricing: ~$10 per 20 pages.
  • Revenue Split: 50% to the Course Creator ($5), 50% to the Platform ($5).
  • Community Editing: Public courses can receive "Change Requests" (similar to Pull Requests) from other teachers.
  • Conversion: Public courses can be converted to Private courses.

Private Courses

  • Visibility: Hidden from the public marketplace.
  • Usage: The course owner can purchase access for their own students (~$10 per 20 pages).
  • Sharing: The owner can share a private course via a link/code to specific other teachers.
  • Shared Teacher Usage: If Teacher B receives a shared private course, they must still pay ~$10 per 20 pages for each of their students.

Anti-Piracy / Sharing Loopholes

  • Risk: A person pretends to be a teacher, receives a shared course, and projects it on a screen for free.
  • Solution 1 (Mandatory Purchase): To unlock the "Teacher Presentation Mode", the receiving teacher must purchase at least 1 student license.
  • Solution 2 (Loss of Interactivity): If they only project it, their students cannot use the interactive tablets. The core value of EduSphere requires student licenses to sync data.

Student Quota Management (Consumable Seats)

  • Finite Resource: Student quotas are treated as consumable tickets rather than a maximum concurrent limit.
  • Permanent Deduction: When a student is enrolled (manually, via CSV, or by approval), a seat ticket is permanently deducted from the course's quota.
  • No Refunds on Removal: Removing a student from a course does not refund the seat. This strictly prevents teachers from reusing a single pool of 30 free seats year after year for new classes.
  • Recurring Revenue: To teach a new batch of students the following year, educators must purchase additional seat quotas.

3. DIY Uploads (Self-Service)

  • Educators with technical skills can write their own HTML/Interactive code and upload it directly.
  • Incentive: They receive 30 free student enrollments for uploading their own content.

4. Monetization Strategy: Token System

The platform will use a Virtual Token System (e.g., "EduCoins") instead of direct Fiat payments.

  • Reduced Transaction Fees: Buying a $4 student license directly loses 10% to credit card fees. Buying a $50 Token Bundle reduces the fee impact.
  • Psychology: Spending virtual tokens encourages more microtransactions.
  • Ecosystem Lock-in: Leftover tokens encourage users to return to the platform.
  • Rewards: Tokens can be given away easily (e.g., "Get 300 Tokens for uploading a course!").
  • Note on Refunds: Refunds will be issued in Tokens, or if real money is required, fiat value will be tracked strictly.
