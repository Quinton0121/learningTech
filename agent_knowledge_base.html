Session: July 26, 2026

Features Built: Real-time Teacher-Learner Slide Synchronization, Presence Tracking, and Mobile Compatibility

🚨 CRITICAL FIX: Next.js 15 Local Network JS Hydration Block (Mobile Devices Dead)

The Problem: When testing the application on mobile devices (iPad, Xiaomi phone) via the local network IP (e.g., 192.168.31.222:3000), the page loaded statically but all buttons and JavaScript were completely dead.

The Cause: Next.js 15+ introduced a strict security policy in Development Mode that blocks cross-origin requests for Webpack HMR and JS chunks from other devices on the LAN. The server silently rejects the request, preventing React from hydrating on the client device.

The Fix: You MUST explicitly whitelist the local network IPs in next.config.ts:

const nextConfig: NextConfig = {
  allowedDevOrigins: ['192.168.31.222', '192.168.31.0/24'],
};

🚨 CRITICAL FIX: iOS Safari Modal Clipping (Position Fixed Bug)

The Problem: The Auth modal (position: fixed) was not showing up on iPads/iPhones. The buttons worked, React state updated, but the modal was invisible.

The Cause: Apple's WebKit engine (Safari/Chrome on iOS) has a notorious bug: If a position: fixed element is deeply nested inside a container (like <main>) that has overflow: hidden or a CSS transform, the fixed element gets clipped or trapped inside that container's boundaries.

The Fix: Extracted the modal rendering logic OUTSIDE of the <main> tag using React fragments (<>...</>), making it a direct child of the <body> where iOS cannot clip it.

🚨 CRITICAL FIX: iPad/iOS Touch Hover States

The Problem: Tailwind's group-hover utility works great for mice, but on touch devices, tapping the element did nothing, making the active students tooltip inaccessible.

The Cause: iOS Safari ignores :hover states on taps unless the element is considered "interactive".

The Fix: Added tabindex="0" and an empty onclick="" attribute to the parent div.group. This tricks iOS Safari into treating the element as clickable, instantly making the hover tooltip work perfectly on touch.

🏗️ Architecture Note: Smart Polling for Synchronization

Context: A 1-second polling interval for 35 students generates minimal bandwidth (~3 Mbps) but causes high database read volume (35 reads/sec). A 10-second polling interval saves resources but creates unbearable lag for the Teacher.

Implementation: Implemented a dynamic setTimeout polling loop. When the class is in "Independent Mode", the client polls every 10 seconds. When the teacher clicks "Synchronize", the client instantly shifts to 1-second polling. This delivers a 0-lag presentation experience while conserving resources during downtime.

🏗️ React Note: textContent vs innerHTML

Context: Using .textContent to inject strings that contain HTML tags (like <span class="lang-en">) will literally render the HTML code as text on the screen.

Implementation: When dynamically updating bilingual text via JS, use JS ternaries to select the plain text string based on localStorage.getItem('courseLang') rather than injecting raw HTML. This avoids both XSS risks and broken UI.
